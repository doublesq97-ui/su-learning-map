# End-to-end workflow

## Phase 0 — Frame

Define the learner's desired capability, not just the source title. Decide whether the target is a perspective Skill, topic framework, learning map, or the full system.

Success criteria:

- one named learner and use situation;
- explicit private/public boundary;
- explicit deliverables;
- no unresolved collision with an existing Skill.

## Phase 1 — Acquire and normalize

1. Inventory local sources.
2. For public people or changing topics, collect current web sources.
3. Prefer authored books, official sites, full interviews, and actual decisions.
4. Add external criticism and contradictory evidence.
5. Record URL, date, source type, evidence grade, topic coverage, and limitations.

Do not store a whole copyrighted work in a distributable Skill. Keep private source files separate from public summaries.

## Phase 2 — Distill

For a person, use six research dimensions: writings, conversations, expression, external views, decisions, and timeline. Extract 3-7 generative mental models, decision heuristics, expression DNA, counterexamples, tensions, and honest boundaries.

For a topic, extract shared foundations, competing schools, decision rules, disagreements, and scope boundaries. Do not imitate a person for a topic Skill.

## Phase 3 — Convert to learning content

Build learning paths around capabilities. A path title should describe a learner transformation, not a source chapter.

For each concept:

1. define it in plain language;
2. state the judgment it enables;
3. attach evidence and locator;
4. include one limitation or misuse warning where material;
5. ask a practice question tied to the learner's life;
6. link it to adjacent concepts.

## Phase 4 — Productize

Write the product sentence:

```text
[Learner], when returning to this body of knowledge, needs to turn one concept into a usable judgment, so the map helps them continue one lesson. Success is a written answer plus a progress mark; if blocked, they can search the directory or switch paths.
```

Keep the cover to one dominant action. Put path explanation on the next screen. Reveal persistent reader controls only inside the learning surface.

## Phase 5 — Build and verify

Run the deterministic builder. Test:

- schema and relationship integrity;
- source locators and evidence labels;
- first concept render;
- search and path switching;
- notes persistence and progress state;
- cover CTA to reader;
- 1440px desktop and 390px mobile;
- no horizontal overflow, missing assets, or browser errors.

## Phase 6 — Deliver

Install only approved Skills. Package only files needed by the map. If deploying, state whether the URL is public, link-only, or authentication-protected. Preserve a short calling guide in the user's operational knowledge base.
