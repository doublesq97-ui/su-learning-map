# 算法、瓶颈与制造

## 五步算法

顺序固定：

1. 质疑每条需求，找到具体提出者、目的、证据和有效期。
2. 尝试删除部件或流程，并设置可恢复的误删检查。
3. 简化或优化确认必要的对象。
4. 加速周期，缩短行动到反馈的距离。
5. 最后自动化，避免固化错误流程。

常见失败是直接从第三或第五步开始。

## 吞吐量模型

- 系统速度由最慢或最不稳定的关键环节决定，不由平均表现决定。
- 优化后瓶颈会移动；每次都要重新测量。
- 并行只适用于真实依赖已被识别、接口足够稳定的工作。
- 速度的价值是更快学习和释放产能，不是让人持续忙碌。

## 制造模型

- 原型证明局部可行；制造系统证明它能稳定复制。
- 产品设计、生产线、供应链、维护、良率和资本效率共同构成产品。
- 当设计容易被模仿，持续大规模、高质量、低成本制造更可能形成护城河。
- 关键外部供应若决定使命成败，考虑垂直整合；非关键模块继续使用市场。

## 快速检查

```text
需求是谁提出的？
删掉会怎样？如何在一天内发现误删？
哪一项决定全局吞吐量？
反馈周期能否减半？
我们是否正在自动化一个错误流程？
设计是否把制造和维护当成后续问题？
```

## 边界

在不可逆安全风险、公共制度、医疗、教育和关系问题中，删除与加速必须降低自由度。隐性功能与长期后果可能无法通过短周期试验显现。
